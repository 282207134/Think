# 项目架构说明

## 设计来源与页面定位

原文件为 Pixso **Think UI Kit**，包含 11 个业务分类、Style Guide 和 Symbols。项目读取了每个业务分类的所有顶层界面，未只读取当前选中页面。120 个界面的名称、节点 ID 与截图见 [截图索引](screenshots/README.md)。

两个分类都包含名为 `Filters` 的页面：媒体滤镜使用 `0:2137`，商城筛选使用 `0:3731`。内部路由以节点 ID 定位，避免同名页面冲突。

## 分层

| 层 | 文件 | 职责 |
|---|---|---|
| 启动 | `lib/main.dart` | 并行加载设计与偏好，显示加载和失败重试 |
| 应用 | `lib/app.dart` | Material 主题、Navigator 路由、目录快捷键 |
| 设计模型 | `lib/core/design/design_catalog.dart` | 解析不可变节点、样式、路径与离线图片 |
| 图形 | `lib/core/design/design_painter.dart` | Flutter Canvas 矢量、原生文字排版、图片填充、蒙版与阴影 |
| 页面 | `lib/features/scene/scene_page.dart` | 固定页头/页脚、滚动主体、横向列表、输入与行为连接 |
| 控件语义 | `lib/features/scene/scene_controls.dart` | 根据组件名和文字识别按钮、输入、开关、计数器、卡片与标签 |
| 状态 | `lib/core/state/app_state.dart` | ChangeNotifier、本地偏好、购物车金额、消息与演示状态 |
| 目录 | `lib/features/catalog/catalog_page.dart` | 分类、搜索、共用渲染器生成缩略预览 |

调用顺序为：启动加载 `DesignCatalog` → 路由选择 `DesignNode` → `ScenePage` 分层绘制并装配交互 → 用户操作更新 `AppState` → `AnimatedBuilder` 更新受影响页面。

## 渲染与原生交互

原稿由大量带绝对位置的矢量、布尔路径与蒙版构成。保留这些几何数据能减少批量重写布局造成的偏差。渲染器将它们转为 Flutter `Path`、`Canvas`、`TextPainter` 和本地图片填充，而非整页位图。

- 节点保存相对界面的绝对变换矩阵，避免 Pixso GROUP 坐标语义差异导致位置错乱。
- 布尔路径使用 `Path.combine`，蒙版使用裁切，颜色覆盖实例继续应用到矢量轮廓。
- 原生文字使用 Montserrat、Bebas Neue、Dancing Script；支持对齐、字间距和行高。
- 页头、状态栏、底栏与操作区为固定层；内容主体可纵向滚动。
- 故事、商品、专辑等超出屏宽的列表使用原生横向滚动容器。
- 输入框、开关、进度滑块与点击区域是 Flutter Widget，并添加可访问性标签。绘制层的 `hitTest` 返回 false，防止固定视觉层挡住正文控件。
- 参考稿中的键盘属于原设计内容；点击输入框时使用系统真实输入法。状态栏和 home indicator 也保留原设计，移动端使用沉浸显示避免重复系统栏。

本次侧重界面完整还原与演示交互，未实现自由重排的平板专用布局。375 × 812 设计区按比例适配可用窗口；大屏保留留白。

## 数据编译与资源

`tool/compile_design.py` 从 `docs/design/raw/design.json.gz` 与 `components.json` 读取只读归档：

1. 保留分类、界面名称、节点 ID、位置、文字、组件语义。
2. 合并等价样式，矢量路径单独去重。
3. 清除运行时不使用的冗余字段，坐标保留三位小数。
4. 输出 `assets/catalog/think.json`，引用 `assets/design/` 中的本地资源。

运行时数据约 1.5 MB，包含 905 份样式和 411 组路径。82 张图片缩至适合展示的尺寸并压缩，共约 5 MB；保留透明图片。一个无法取得原始字节的设计图片使用对应节点的导出资源补齐。原始节点归档约 0.5 MB，可重复生成数据。

项目没有运行时网络图片请求，不依赖 Pixso 插件或 localhost 临时链接。路径与几何形状缓存，图片解码结果在页面和缩略图之间共用。

## 状态与业务边界

持久化键为 `think.state.v1`，通过 `shared_preferences` 存储：

- 收藏与关注/开关状态；
- 购物车各预置商品数量；
- 聊天演示消息、新增待办、显示姓名。

登录状态与播放器状态为内存演示状态。密码、支付卡号与输入中的表单内容不写入偏好。偏好格式损坏时清除该演示状态键并使用默认数据。

购物车价格集中在 `AppState.cartPrices`，数量、件数和合计使用同一来源。结算时将合计传到支付页，避免页面间金额不一致。直接从目录进入支付页时，保留原设计的静态示例金额。

账户、支付、通话、音乐、相机、地图等外部服务均未接入。标签、部分筛选和图表只提供界面选中反馈；图表数值与图形仍是设计样例。真实后端应通过新增 repository/service 层接入，再由 `AppState` 或独立 feature controller 调用，不应写入绘图层。

## 扩展约定

新增或调整界面：先更新只读设计归档并运行编译脚本，再检查节点对应的点击区域和原生控件，最后更新截图。新增纯行为可修改页面行为映射，无需改矢量数据。

若业务需要深入扩展某个页面，可将该页面逐步替换为专用 Widget，同时复用 `AppState` 与导航接口。共用渲染器适合保留 UI Kit 的完整变体；复杂表单、实时列表和可访问性要求较高的生产页面适合独立组件化。

路由 `/screen/<URL 编码后的节点 ID>` 可直接定位界面。跨页面名称重复时始终传节点 ID。
